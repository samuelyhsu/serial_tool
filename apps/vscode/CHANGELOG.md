# 更新日志 · Changelog

本文件记录「Serial Tool」扩展的变更。
格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循
[语义化版本](https://semver.org/lang/zh-CN/)。

## [未发布]

### 新增

- 多条发送可以**拖动重排**了：分组标签按住左键左右拖、预设行按住**数据框**上下拖。
  数据框兼作拖拽手柄，横着拖仍然是选文本。键盘那条路也有：分组按 `Alt+←→`，
  预设行仍是 `Alt+↑↓`。
  两点注意：分组顺序变了，顺序循环的发送次序也跟着变（它本来就是按预设顺序跨分组发的）；
  还没改过名的分组会在第一次重排时把「分组 N」固化成真名，否则标签文字按位置生成、
  拖完还留在原地，看起来像没生效。

### 变更

- 多条发送的每行去掉了发送按钮后面那个「✎」，改名改为**在行内按 F2**。
  F2 挂在整行而不是发送按钮上：用鼠标聚焦发送按钮的唯一办法是点它，而点一下就把报文
  发出去了。点数据框再按 F2 才是安全的路径。省下的一列宽度归了数据框。
- 发送按钮的悬停提示改为说清这一行能按什么（F2 改名、Alt+↑↓ 调顺序）；原来挂在那儿的
  `Alt+数字` 提示已删 —— 那条快捷键本身早就移除了，提示却还在。
- 分组标签的悬停提示补上了 `← →` 切换与 `Home` / `End` 到首尾。

### 新增

- 接收区工具栏新增「● 录制」：点一下选文件，此后收发数据边收边写进去，再点一下结束。
  它不受日志缓冲条数限制 —— 挂一夜等偶发问题时，缓冲装不下的那些以前直接就没了。
  文件里的 TXT / HEX 格式在点下那一刻定死，时间戳带日期，只记收发帧不记系统消息
  （文件头里写明了）。**录制跑在扩展宿主进程**，面板隐藏、切到别的编辑器标签都照写，
  与周期发送同一个理由；面板关掉时会自己收尾，不会漏下一个写到一半的文件。
- 工具栏上新增控制信号线：`DTR` / `RTS` 两个开关、一个 250ms 的 `BRK` 脉冲，
  以及 `CTS` `DSR` `DCD` `RI` 四盏每秒刷新的指示灯。手动把板子拉进 bootloader、
  复位 STM32、用 Break 打断 U-Boot 以前在这个工具里做不到。
  DTR / RTS 显示的是本工具最后一次设置的值——这两条是输出线，读不回来；端口刚打开时
  它们由驱动决定，工具不会替你再下发一遍（那会多出一个复位脉冲）。
  VS Code 里读不到 `RI`，那盏灯恒灭。
- 单条发送记住发过的最近 20 条：底部「历史」下拉点一下填回输入框，输入框里
  `Ctrl+↑` / `Ctrl+↓` 也能翻。条目带 TXT / HEX 标记（同一串字符在两种模式下是
  完全不同的字节），只记真的写出去了的。
- 过滤框旁新增 `.*` 开关：把过滤词当正则表达式（与子串模式一样不区分大小写）。
  正则写到一半时不过滤也不高亮，输入框标红并把那句错误挂在提示上，而不是把日志清空。
- 接收区工具栏新增「⏸ 暂停」：把画面定住看一眼，数据照收照存、只是不往上刷，
  旁边显示这期间新到了多少条（不说的话，「暂停了」和「设备不发了」看起来一模一样）。
  往上滚会自动暂停、滚回底部自动恢复；手动按下的那次要再按一次才恢复。
- 接收区的「时间戳」复选框换成一个四选一的下拉框：不显示 / 时间 / 日期+时间 / 间隔。
  「间隔」显示与上一条的时间差（`+12ms`、`+1.500s`）—— 调协议时序最常看的就是这一列，
  以前只能自己拿两个时间戳相减。它算的是缓冲里物理上的上一条，隐藏 TX 行不会让间隔变大。
  原来存着的「显示时间戳」开关会自动迁移，设置不会被重置。
- 保存日志与录制文件的时间戳都带上了日期。跨夜的日志导出后只有时分秒，拿到手连是哪天的
  都说不清。

## [0.6.0] - 2026-09-18

### 新增

- 输出面板里新增「串口助手」日志频道：原生模块加载失败、端口枚举失败，以及打开失败、
  读写错误、掉线与重连等会话事件都记在这里，每行带上端口，报问题时可以直接贴出来。
  日志级别跟着「Developer: Set Log Level」走。
- 在 Remote-SSH、WSL、开发容器里若扩展运行在远端，端口视图标题旁会标出「远端：ssh-remote」
  之类的来源；远端找不到串口时，提示会说明是远端没有，并指出本机设备需要把扩展装到本地。
- 打开串口失败、且底层明确报告端口被占（Windows 的 Access denied，Linux / macOS 的端口锁
  失败）时，提示会补一句「端口可能正被其他程序或另一个 VS Code 窗口占用」。多个 VS Code
  窗口之间无法互相登记占用，以前这种情况只看得到一句 Access denied。
- 接入 VS Code 的 AI 聊天：在 agent 模式下，或用 `#serialPorts`、`#serialOutput`、`#serialSend`
  引用，助手可以列出串口、读取面板已捕获的收发数据、向已打开的串口发送数据。它不能打开或关闭
  端口；每次发送都会弹出确认框，写明端口与要发的字节。助手读到的串口数据会交给聊天所用的模型。

### 变更

- 最低支持的 VS Code 版本由 1.75 提高到 1.95（2024 年 10 月发布），为接入 AI 聊天的
  工具调用做准备。更老的 VS Code 会停留在 0.5.x。

### 修复

- 工作区处于受限模式（打开文件夹时选了「不信任」）时，扩展不再被整个禁用。
- 使用 Remote-SSH、WSL、开发容器时，本机装有本扩展就优先在本地运行，端口列表显示的是
  插在本机上的设备，而不是远端机器上的（远端往往一个都没有）。

## [0.5.1] - 2026-09-17

### 修复

- 多条发送的分组多了之后，标签栏不再把右栏撑宽、把「+」「−」和导入导出挤到可视区外；
  放不下的分组在标签栏里横向滚动，这几个按钮始终完整显示。
- 切到别的标签页一段时间再切回来，接收区里后台期间收到的数据不再被攒成一整块上千字符的
  超长行（这种行一多，切回来后界面明显卡顿、绘制跟不上）。空闲分帧此前只靠定时器判断
  「静默了」，而浏览器会把后台标签页的定时器限流到至少 1 秒一次，数据只要持续在来，
  定时器就一直触发不了；现在按数据实际到达的间隔成帧。

## [0.5.0] - 2026-09-17

### 新增

- 多条发送可以删除分组：选中后点标签栏的「−」或按 Delete。没动过的空分组直接删；有内容的
  分组要再点一次「确认删除？」，3 秒内不点就复原。只剩一组时不能删，组里正在循环的预设会
  一并停下。
- 记住多条发送当前选中的分组：刷新页面，或在 VS Code 里切走编辑器标签再切回来，仍停在
  原来那一组。

## [0.4.0] - 2026-09-17

### 变更

- 去掉接收区、单条发送、多条发送三个区域左上角的标题，屏幕阅读器仍按这三个名称识别它们。
- 多条发送的翻页改成分组标签页：默认 3 个分组、每组 10 条；双击分组标题（或选中后按 F2）
  改名，点「+」新建分组。升级前用过的预设原样保留，末尾没用过的空页不再显示。导出的文件
  换成带分组的新格式，旧文件仍可导入。

## [0.3.0] - 2026-09-17

### 新增

- 活动栏的端口列表显示你在面板里给端口起的备注名（如 `温控板 · COM3 · CH340 (1A86:7523)`），
  改完立刻生效，不必重开 VS Code。
- 波特率候选从 32 档补全到 51 档（50 ~ 4000000），汇总 Windows / Linux 的标准档与
  CP210x、CH340 芯片手册里的档位，另含 ESP8266 上电日志用的 74880。

### 变更

- 波特率下拉点开总是列出全部档位，并高亮当前值；边打字边按开头数字筛选。
  此前框里是 115200 时点开只剩 115200 / 1152000 两项，想换档得先把值删掉。
  筛选时直接按 Enter 保留你输入的值，要选候选档先按 ↓。
- 波特率输入框去掉了加减微调按钮，滚轮也不再改值；只接受数字，粘贴 `921,600` 也能用。
- 去掉顶栏标题左侧的「S」图标，它只是装饰。
- 工具栏去掉了连接状态指示（圆点加文字），它与「打开 / 关闭串口」按钮重复。打开过程中
  按钮显示「打开中…」；自动重连期间按钮变成琥珀色，悬停可见「重连中…」，点它照旧会停止
  重连并关闭串口。
- 语言切换按钮的文字由「EN / 中文」改为「EN / CN」。
- 状态栏去掉了「端口 @ 波特率 8N1 · 流控」这段摘要，顶部工具栏上这些一直都显示着。

### 修复

- 调大日志缓冲容量后，面板隐藏再显示（比如切走标签页再切回来）不再只剩默认的 10000 条。
  此前扩展宿主那份缓冲始终按默认容量保留，重建出来的面板也会退回建面板时的容量。
- 面板隐藏再显示后，打开面板之后改过的设置不再退回原样。此前指令预设、主题、手动切换的
  界面语言、端口备注、各设备的串口参数等都会回到打开面板时的值，接着再改一次预设还会把
  之前改好的列表覆盖掉。在别的面板里改的设置，隐藏着的面板重新显示时也会跟上。

## [0.2.0] - 2026-09-13

首次发布到 VS Code Marketplace 与 Open VSX。

> **从 0.1.0 升级**：0.1.0 是以「串口助手 · Serial Assistant」
> （`samuelyhsu.web-serial-tool-vscode`）的名义随 GitHub Release 分发的，本版起扩展 ID
> 改为 `uplume.serial-tool`。两者的命令 ID 相同，同时装着会有一个激活失败 ——
> 请先卸载旧版再安装。旧版存下的偏好不会带过来。

### 新增

- 面板左下角（状态栏最左侧）显示版本号，反馈问题时一眼能看出用的是哪一版。
- 日志缓冲容量可在接收区工具栏调整：默认 10000 条，不少于 1000，不设上限。
  列表最多渲染最新 1000 行（原先 600 行），更早的记录在列表顶部标明条数，
  点「保存」可导出完整日志。

### 变更

- 扩展改名为 Serial Tool，名称与简介跟随 VS Code 显示语言，中文环境下显示为
  「串口助手」；商店页补上英文说明。
- 「清空」改为按两下：第一下按钮变成「确认清空？」，3 秒内没有再按就复原。
  这一步不可撤销，会丢掉缓冲里的全部采集数据与统计，而按钮就紧挨着「保存日志」。
- 多条发送的底部压成一行，矮窗口下能多显示几条预设；「全部停止」只在有周期任务
  运行时出现。

### 修复

- 「清空」现在会连扩展宿主保留的那份日志历史一起丢。此前它只清了面板这一侧，
  宿主的环形缓冲毫不知情 —— 面板一隐藏再显示，快照回放就把清掉的日志连同
  统计原样带了回来。
- 英文 VS Code 里，标签页标题、状态栏、端口选择框与端口视图不再显示中文，
  跟随 VS Code 的显示语言。
- 手动切换的界面语言不再在面板隐藏又显示之后被改回去。
- 矮窗口下单条发送区不再被挤到溢出（HEX 报错行出现时尤其明显）。
- 面板里的西文字体跟随 VS Code 的工作台 / 编辑器字体设置（此前变量名写错，从未生效）。

## [0.1.0] - 2026-08-30

首个版本。

- 一个面板 = 一条会话 = 一个端口，可同时开多个面板各连一口。
- 串口会话跑在扩展宿主进程：面板被隐藏、切去看代码，串口不会断，周期发送照跑。
- 活动栏端口视图：点一个端口直接连上；已连接的口标注占用者。
- HEX / 文本双视图、接收分帧（原样 / 空闲超时 / 按换行）、校验和、周期发送、
  发送预设、断线自动重连。
- 设备身份带序列号，换 USB 口也认得出来；备注与波特率按设备记忆。
- 状态栏在写队列有积压时显示积压字节数，作为背压的直接观测点。
- 设置存在 VS Code 的 globalState 里，可随 Settings Sync 跨机器同步。

> 本版尚未发布到 Marketplace，只随 GitHub Release 分发 VSIX。
> 扩展形态下的人工验收清单（见仓库 README「测试」一节）尚未完整走过一遍。
